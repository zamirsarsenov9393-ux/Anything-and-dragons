# Движок правил (этап 2)

Версия движка: 0.2.0. Код: `src/core/`. Ни React, ни база данных, ни браузерные API здесь не используются.

## Как пользоваться

```ts
import { compute } from './core/engine/compute';
import { MemoryResolver } from './content/resolver';

const resolver = new MemoryResolver([srd521], snapshots);
const { sheet, pending, issues, usedContent } = compute(build, resolver, { equipment });
```

- `build` — журнал решений персонажа (`CharacterBuild` в `src/core/types.ts`).
- `equipment` — надетые и взятые в руки предметы из инвентаря.
- `sheet` — готовый лист. У каждого числа есть `components`: из чего оно сложилось и что не применилось.
- `pending` — выборы, которые пользователь ещё не сделал. Мастер создания покажет их по уровням.
- `issues` — ошибки (`error`), предупреждения (`warning`) и пояснения (`info`).
- `usedContent` — какие элементы и каких версий повлияли на расчёт. Сохраняются вместе с ревизией персонажа.

## Файлы

| Файл | Что делает |
|---|---|
| `core/formula.ts` | Язык формул: разбор в дерево, вычисление. Без `eval`, неизвестные имена отклоняются |
| `core/predicate.ts` | Условия эффектов: доспех, щит, уровень класса, характеристика, особенность, предмет |
| `core/editions/index.ts` | Правила 2014 и 2024: бонус мастерства, модификаторы, покупка очков, таблица ячеек, уровень заклинателя, хиты, грузоподъёмность |
| `core/engine/compute.ts` | Конвейер расчёта и валидация |
| `content/resolver.ts` | Доступ к контенту в памяти, снимки механики для отключённых источников |
| `content/hash.ts` | SHA-256 и канонический JSON для версий элементов |

## Порядок расчёта

1. Вид и подвид, предыстория (2024: +2/+1 или +1/+1/+1 и черта происхождения).
2. Уровни 1…N по порядку: стартовые владения или владения мультикласса, особенности уровня, выбор подкласса, особенности подкласса, увеличение характеристик или черта.
3. Экипировка и магические предметы (только настроенные, если нужна настройка).
4. Характеристики: бонусы с пределом 20 (или выше, если эффект поднимает предел), затем «установить значение».
5. Бонус мастерства по общему уровню, владения, компетентность, «мастер на все руки».
6. Спасброски, навыки, пассивная внимательность.
7. КЗ: доспех или 10 + ЛВК, альтернативные формулы — берётся лучшая; щит; бонусы.
8. Инициатива, хиты (модификатор ТЕЛ задним числом ко всем уровням, минимум 1 за уровень), скорость.
9. Заклинательство: СЛ, бонус атаки, лимиты по таблицам или формулам класса, ячейки, магия договора отдельно.
10. Атаки оружием, количество атак, ресурсы, чувства, сопротивления, выданные заклинания.
11. Проверки: способ распределения характеристик, требования мультикласса на момент взятия уровня, требования черт, лимит настройки, предел 20 уровня.

## Различия редакций, которые уже учтены

| | 2014 | 2024 |
|---|---|---|
| Бонусы характеристик при создании | от вида | от предыстории |
| Черты вместо УХ | только при включённом опциональном правиле | всегда |
| Полузаклинатель одного класса | ячейки со 2 уровня | ячейки с 1 уровня |
| Полузаклинатель в мультиклассе | половина уровня вниз | половина уровня вверх |

## Тесты

99 тестов, все зелёные. Покрытие `src/core`: строки 99,8%, ветвления 93,6%. Порог в CI: строки 95%, функции 95%, ветвления 85%.

- `tests/core.unit.test.ts` — формулы (включая 2000 случайных строк), условия, таблицы редакций, SHA-256 против `node:crypto` на 500 случайных строках.
- `tests/engine.scenarios.test.ts` — 12 эталонных персонажей из плана тестирования.
- `tests/engine.effects.test.ts` — каждый тип эффекта и выбора, экипировка, ошибки журнала.

Тестовые пакеты (`tests/fixtures/packages.ts`) содержат только механику по SRD, без текстов. Это не контент приложения: настоящие пакеты SRD 5.1 и 5.2.1 собираются на этапе 3.
